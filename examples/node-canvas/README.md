# node-canvas — эксперимент Фазы 0

Проверка гипотезы из [`rnd/architecture.md`](../../rnd/architecture.md) §16: можно ли
построить нод-редактор уровня Blender поверх `masonry_core`, не форкая его.

```bash
cargo make run-node-canvas                   # интерактивное окно
cargo make bench                             # замеры headless и критерии
cargo make bench -- --quick                  # только сценарии, по которым решаются критерии
cargo make bench -- --nodes 20000
cargo make bench-ci                          # то же + JSON-отчёт в target/bench-report.json
```

Замеры — отдельная цель `benches/phase0.rs` с `harness = false`, а не флаг у окна:
профиль `bench` наследует `release`, так что оптимизацию не нужно помнить руками, и
бенч-код не попадает в бинарь окна. Прогон возвращает ненулевой код, если хоть один
критерий Фазы 0 перестал выполняться, поэтому CI гоняет его наравне с тестами.
Почему ни `#[bench]`, ни `criterion` не подходят — в шапке `benches/phase0.rs`.

## Управление

| Действие | Клавиши |
|---|---|
| Перетащить ноду | ЛКМ по телу ноды |
| Панорамировать | ЛКМ по пустому месту, либо СКМ |
| Зум к курсору | Колесо |
| Контролы | Слайдеры и чекбоксы внутри нод работают на любом зуме |

Внизу окна — счётчики: видимые/всего, зум, уровень LOD, число проходов layout и
compose. Именно они, а не «на глаз», отвечают на вопрос Фазы 0.

## Что проверяется

1. **Пан и зум стоят один `Affine`** — не должны перезапускать layout детей.
2. **Culling** — вне вида ноды не должны стоить ничего.
3. **Обычные виджеты внутри нод** — без правок в самих виджетах.

## Результат

Первая версия использовала `set_stashed` для culling — и провалилась: стоимость кадра
оказалась линейной по **общему** числу нод (64× нод → 81× времени) при неизменной
видимой части. Сташенный виджет остаётся в дереве, а проходы Masonry рекурсируют по
всему дереву.

Канвас переписан на **виртуализацию**: нода вне кадра удаляется из дерева, состояние
живёт в модели графа. После этого:

| | было | стало |
|---|---:|---:|
| idle | 6.79 мс | 0.118 мс |
| пан | 21.05 мс | 0.838 мс |
| 64× нод | 81× времени | **1.1× времени** |

Отдельно решён обзорный масштаб, когда виден весь граф: ниже порога читаемости канвас
не строит виджеты, а рисует ноды сам, одним проходом в свою сцену (43.2 → **1.6 мс**).

Все критерии Фазы 0 пройдены — и с тех пор проверяются на каждый push, а не
единожды руками. Полный разбор — [`rnd/architecture.md`](../../rnd/architecture.md) §20,
устройство гейта — §20.9.

## Структура

| Файл | Содержимое |
|---|---|
| `lib.rs` | Сборка канваса над сгенерированным графом — общая для окна, замеров и тестов |
| `main.rs` | Интерактивное окно |
| `benches/phase0.rs` | Точка входа замеров, разбор флагов, код возврата |
| `editor.rs` | `NodeEditor`: канвас плюс HUD со счётчиками |
| `node.rs` | `GraphNode`: тело ноды со слайдером и чекбоксом, LOD через свойство |
| `model.rs` | `GraphModel`: состояние нод, источник истины при виртуализации |
| `bench.rs` | Сценарии замеров и вычисление критериев Фазы 0 |
| `criteria.rs` | Критерии как проверяемые утверждения, вердикт, JSON-отчёт |
| `tests.rs` | Тесты корректности виртуализации |

Сам канвас — в [`crates/blazy-canvas`](../../crates/blazy-canvas).
