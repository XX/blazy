# area-screen — эксперименты Фаз 0.5 и 0.6

Проверка второй половины вопроса Фазы 0. Фаза 0 установила, что стоимость кадра —
это стоимость обхода дерева виджетов, а дерево одно **на окно**
([`rnd/architecture.md`](../../rnd/architecture.md) §20.2). Нод-канвас ушёл от этого
виртуализацией, но экран Blender держит в том же окне шесть-восемь редакторов сразу,
и ни один замер до сих пор не говорил, складываются ли их стоимости и не
перекладывает ли перетаскивание сплиттера весь экран.

Фаза 0.6 добавляет к этому вторую половину §9: у каждой области есть регионы
(шапка и main), у каждого региона — свой `ui_scale`, и вопрос в том, остаётся ли он
входом **layout**, не утягивая за собой `view`, который обязан жить только в paint.

```bash
cargo make run-area-screen                   # интерактивное окно
cargo make run-area-screen -- --areas 16
cargo make run-area-screen -- --ui-scale 2   # все шапки одного масштаба
cargo make bench-areas                       # замеры headless и критерии
cargo make bench-areas -- --quick
```

Окно открывается с **разным `ui_scale` у каждой области** — одна и та же шапка из
одного и того же виджета в четырёх размерах в одном окне, при нетронутых канвасах под
ними. Это видно глазом быстрее, чем читается в числах.

Каждая область держит нод-канвас над **одним общим графом** — так числа сопоставимы
с Фазой 0, и развёртка по числу областей меняет только разбиение, а не данные.

## Что проверяется

1. **Области не складываются.** Разбиение окна не добавляет виджетов в дерево, а
   делит тот же вьюпорт на меньшие куски.
2. **Перетаскивание сплиттера трогает двух соседей, а не экран.** Перекладываться
   имеют право только области, у которых реально изменился прямоугольник.
3. **Простаивающий экран простаивает.** Пересчёт прямоугольников каждый кадр — не то
   же самое, что раскладка.
4. **`ui_scale` идёт в layout и остаётся в своём регионе.** Смена масштаба обязана
   доехать до раскладки региона и не обязана задевать ни область, ни соседей.
5. **`view` в layout не идёт.** Зум содержимого не имеет права ресайзить регион.

## Результат

Все критерии проходят. Полный разбор с числами —
[`rnd/architecture.md`](../../rnd/architecture.md) §21 и §22.

| Сценарий (8 областей, 5000 нод) | мс/кадр | ресайзов областей | ресайзов регионов |
|---|---:|---:|---:|
| простой | 0.166 | 0.00 | 0.00 |
| перетаскивание листового сплиттера | 0.320 | **2.00** | 4.00 |
| перетаскивание корневого сплиттера | 0.556 | 4.10 | 8.20 |
| пан внутри одной области | 0.240 | 0.00 | 0.00 |
| смена `ui_scale` одного региона | 0.308 | **0.00** | 1.95 |
| зум содержимого одного региона | 0.325 | 0.00 | **0.00** |

Развёртка по числу областей — 1 → 16 при неизменном окне и графе: живых виджетов
35 → 49, простой 0.097 → 0.140 мс. Стоимость определяется окном, а не разбиением.

## Структура

| Файл | Содержимое |
|---|---|
| `lib.rs` | Сборка экрана: дерево сплитов, регионы и канвас в каждой области |
| `header.rs` | `ScaledHeader`: шапка региона, честно читающая `UiScale` в layout |
| `main.rs` | Интерактивное окно |
| `benches/screen/main.rs` | Точка входа замеров: флаги через `clap`, отчёт, код возврата |
| `benches/screen/bench.rs` | Сценарии замеров и вычисление критериев Фазы 0.5 |

Сама подсистема областей — в [`crates/blazy-areas`](../../crates/blazy-areas),
модель графа переиспользуется из [`examples/node-canvas`](../node-canvas).

## Чего здесь нет

Ни join, ни maximize/restore, ни swap, ни отсоединения области в отдельное окно, ни
регионов кроме шапки и main. Это функциональность; спайки существуют, чтобы выяснить,
здорова ли форма, на которой её строить.

Отдельно: **встроенные виджеты Masonry `ui_scale` не читают** — ни один из них не
знает про это свойство, а их размеры приходят из `DefaultProperties`, которые одни на
приложение. Это измерено тестом `masonry_widgets_do_not_follow_ui_scale`, разобрано в
§22.1 и требует изменения в апстриме.
