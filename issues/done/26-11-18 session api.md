# Аксессоры сессии вместо публичных полей

Находка 11 из §63.2. `EditorSession` и `EditorWorld` — структуры с публичными полями (`runtime`,
`world`, `editor`, `sidebar`; `hover`, `pointer`, `scale`, `band`, `ports`, `link_preview`…).
Приложение пишет `session.borrow().world.graph`, чтобы достать граф для панели, и ничто не мешает
ему переписать `hover` посреди жеста. Любое внутреннее поле — часть API, и каждое изменение
мира ломает приложения.

## Вопрос

Что из сессии и мира нужно приложению — и что нужно только операторам и драйверу, — и как
закрыть остальное, не потеряв тестов редактора, которые сейчас пишут поля напрямую?

## Разведка

* **Кто что читает.** Пройти `hello`, `calc`, `area-screen`, `blazy-app` и тесты: составить
  список полей, которые читаются и пишутся снаружи крейта.
* **Операторы приложения.** Оператор, написанный приложением, получает `OpCtx<EditorWorld<G>>`
  и читает мир — значит, часть мира остаётся API, но через методы.
* **Тесты.** Тесты редактора ставят `hover` и `pointer` руками; им нужен тестовый вход
  (`#[cfg(test)]` или фича `testing`), а не публичное поле.
* **Перечисления `blazy-ops`.** `Trigger`, `Value`, `OpResult`, `Seat`, `Feed`, `Dispatch`, а также
  `Detail` и `HitMode` остались открытыми в §63.3 — решить вместе.

## Что сделать

1. Список «снаружи читается/пишется» и решение по каждому полю.
2. Поля закрыть, нужное — методами; тесты — через тестовый вход.
3. Перечисления из §63.3 — `#[non_exhaustive]` или запись, почему нет.

## Чем проверяется

* `hello` и `calc` собираются без обращения к полям сессии.
* `cargo make ci`, включая документацию: у каждого нового метода есть документация.

## Чего эта задача не делает

* **Не меняет поведение** — только форму доступа.
